## Conservative lifecycle guard

The first draft incorrectly treated successful Client close as sufficient proof to remove worktrees. Coordinator review caught this before native execution. The corrected guard requires parent completed, equal counts of observed spawn requests and distinct actual child starts, and each observed child's latest turn completed (not a per-call-ID bijection); a later turn start invalidates settlement. Timeout/error, missing start/terminal evidence or cleanup failure preserves worktrees and reports deferred cleanup. Server close alone is never writer termination evidence.

For settled runs, save snapshots, identities, list and native evidence before archiving each task-owned checkout without `.git`. Remove only the exact prepared resolved path with expected branch and unchanged base HEAD; an unexpected state is retained for inspection. Preserve the primary checkout and local bare fixture. No user worktree is discovered or deleted. These checks establish the observed task lifecycle, not phase 4 general recovery or universal host termination semantics.

Model-free tests cover timeout/unknown/restarted activity causing **no Git removal call**, distinct worktree/index/base preparation, archive-before-removal for known-settled paths and preservation of an unexpected HEAD. The normal preflight also successfully archived/removed all three owned linked worktrees and retained only primary. New fixture and tests remain reviewable; one native run requires coordinator approval after this plan and guard review.
