## Reproduce

```sh
bun scripts/validate-codex-plugin.ts
bun test ./scripts/
python3 scripts/smoke-codex-entry.py
```

The smoke script starts a loopback HTTP capture endpoint and temporarily directs a disposable Codex session to it. It observes Codex's actual outgoing context, then terminates the session without obtaining a model response. The configured model name is a local test request field; no paid model or API credential is used. The script checks real host injection rather than relying on skill self-report.

The app-server check used the schema generated by the installed Codex executable and a disposable stdio server. It validates the backend used by local clients; it is not proof that a user has completed the desktop UI flow.

## Authenticated CLI follow-up, 2026-10-22

Client remains `codex-cli 0.163.0-alpha.10.2` on macOS arm64. These turns used the existing ChatGPT login, the CLI's configured model without a model override, ephemeral sessions, a disposable workspace, and the read-only sandbox. They used a real model response, not the local capture endpoint.

| Scenario | Prompt | Observed result |
| --- | --- | --- |
| Ordinary, plugin installed | Ask `7 + 5`, require digits only and no tools | Exit 0, final reply `12`, no tool use |
| Explicit namespaced entry | `$pstack:poteto-mode` and ask whether the entry loaded and full tasks are available, with no mutation or delegation | Exit 0; reads packaged `references/status.md`; replies in Chinese that the entry loaded at 0.1.0-alpha.1 and core workflows are unavailable |
| Explicit project alias | `$poteto-mode` with the same availability request | Exit 0; reads status and states the entry loaded, core execution is pending phase 2, and no files/agents/automation were changed |
| Ordinary, alias also installed | Repeat the digits-only arithmetic request | Exit 0, final reply `12`, no tool use |

The explicit responses correctly listed task routing, custom agents, model setup, persistent checklists, and autonomous work as unavailable. This validates the preview's actual response, not those future capabilities. CLI tool events were inspected; explicit turns only read status and the disposable workspace's README stayed unchanged. Raw account/session logs remain local and are not committed.

The reviewer found that the original `ln -s SOURCE TARGET` example could create a nested link inside an existing directory. The instructions now call `scripts/link-codex-entry.py`, whose atomic symlink creation refuses an occupied path. Four regression tests cover a fresh link, an existing skill directory, a dangling link, and an existing file/already installed link. The preview suite now has 10 passing tests and 20 assertions. The full combined run had 79 passing tests and 267 assertions. The host smoke check uses the same installer and passed again.
