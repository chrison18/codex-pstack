# Phase 5 bounded continuation

Design checkpoint on merged phase 4 base `e430c85`: one invocation drives a finite declared task to a checkable predicate in the active agent turn. Reuse phase 4 task identity, atomic persistence and intent/evidence records; add a continuation grant, frozen goal/requirements/authority/scope/owner, operation budget and durable delivery receipts in the same file. No timer, autonomous external launch or second state store.

`next` atomically issues one pending operation only to a new stable delivery ID. Duplicate IDs authorize nothing, including after process restart. Outstanding started effects stop new issuance until evidence settles them; absence of a receipt is never evidence that an effect did not happen. `finish` records observed results; `close` requires all operations plus separate done-predicate evidence. `cancel` is terminal and preserves in-flight uncertainty; it cannot kill an already running external tool. Phase 4 mutation commands refuse records owned by continuation, preventing terminal-state bypass. A successor needs an explicit reconciled plan, never receipt reset.

Budget exhaustion records incomplete work and a next action, not success. Normal authorized in-turn work continues without asking the user to run helper commands. No arbitrary task execution is hidden in the helper: the agent follows the existing playbook, verifies evidence and calls the controller between effects. This is cooperative control, not hostile-process security or exactly-once external effects.

Host inspection: version-matched Orca guide and `agent launch --help` document one-shot fresh Chat launch and operation-ID retry after ambiguous launch. They do not establish a same-Chat send or recurring wake contract. No external wake adapter is claimed yet; test a narrow explicit delivery boundary or retain that dependency as unsupported. Antigravity schedule/goal/agentapi, Benny Slack/tracker actions and bot UI credentials are not copied or activated. Shipping still needs actual authorization and forge proof.

## A12 disposition and remaining boundary

This increment is ready for review as useful **bounded in-turn continuation** plus a durable synchronous delivery receiver. It covers completion stopping, cancellation interleaving, fresh-process duplicate/restart, uncertainty and concurrent issuance. The native case proves actual package loading and one-request local completion, not every task/playbook or a long-running autonomous service. The local batch is finite task execution in a single foreground tool call, not a background continuation loop.

**External automatic wake/recurring integration: unsupported, NOT RUN.** One-shot Chat launch is callable but is not an installed task-event adapter; no host wake contract was invented, no timer created and no supervisor dispatch counted as autonomy. A12's host-wake part and the full unattended user outcome remain qualified, pending an authorized supported event source/delivery adapter with stable task/event identity and settlement evidence. No external exactly-once, live Chat crash control, hostile-process isolation, forge shipping, Benny messaging or bot credentials are certified.
