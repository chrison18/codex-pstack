# Workflow index

Use only inside an explicitly active Poteto task. Select the narrowest route, then read its full reference and only the dependencies needed for this request. These are internal references, not additional native entries. Follow [runtime](runtime.md), [principles](principles.md) and [status](status.md). A referenced workflow never widens user scope or overrides host permissions.

The primary owns routing, checklist, model resolution, evidence, integration and reply. A new task needs explicit activation; a followup continues the current task. Research/prose/help alone do not authorize writes. A required delegate/tool/model that is unavailable stops that step; report a real limitation instead of inventing a host command. Generic delegated work uses the resolved `swarm-worker` preference unless a specific existing role is named. Never substitute a vendor tier.

Read dependencies before consumers: writing and code rules → app control → verification authoring/maintenance → design/measurement/planning and delivery. Later-phase history and automation are unavailable. The manual multi-phase plan route is narrower than the inherited autonomous program schema.

## Code quality

- [typescript-best-practices](skills/typescript-best-practices.md): model and validate TypeScript data at boundaries without unsafe casts.
- [tdd](skills/tdd.md): capture a cheap failing-before regression and rerun it after the fix.

- [correct](skills/correct.md): prevent repeated evidenced mistakes using the strongest useful enforcement.

- [benchmark-checklist](skills/benchmark-checklist.md): validate workload, limiter, errors, real work and repeated measurements before a performance claim.
