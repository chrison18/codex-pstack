# Blinded workflow evaluation

The primary owns experiment design, blinding, actual evidence and synthesis. Frame the variants and 3–6 concrete success criteria before running; keep the rubric with the judge only. Candidates receive the same organic request in separately owned project-shaped directories and must not know about other candidates or their model labels. Remove evaluation words from candidate-visible prompts/paths (eval, test, judge, experiment, rubric, score, compare, benchmark, candidate, arena). Do not elicit a list of applied skills; inspect actual reads and behavior.

Use [Arena](../arena.md) for independent candidates and completed-writer crossjudging. Resolve all explicit model/effort choices before spawn. Prefer an independent judge on a genuinely different available model; differing model IDs do not prove a different family. If the requested family diversity is unavailable, disclose it rather than substituting or claiming the gate passed. Use separate worktrees for code writers. Each candidate owns only its artifacts and never reads peers. For a blinded request use an available native default agent with forked context disabled, rather than forcing the orchestration entry or rubric into its brief through a custom role. Resolve its model/effort through the same runner contract; this exception changes context delivery, not selection precedence. Scope candidate visibility to the sanitized task tree. Do not claim strict blinding of host metadata that the client inevitably exposes.

After all writers finish, give one blinded judge sanitized output labels and the rubric, with no model identities, then read every output yourself. Reconcile disagreements with actual artifacts and the original criteria. A judge verdict is evidence, not the primary's answer.

Inspect only task-owned native event captures or supported session interfaces. A spawn does not promise a transcript path. Do not glob other chats, invent conversation IDs or scrape a private host store. If the host exposes only encrypted prompts or no child reads, state exactly which chain checks are unobservable. Artifact/behavior results can still be reported, but an unobservable chain is not a pass. Keep raw transcripts private.

Reply with variants, rubric, per-output observations, judge verdict, reconciled conclusion and promotion recommendation. Promotion, installation, PR mutations and external posting need their own authorization.
