# Investigation

This route produces a cited answer or recommendation. It does not authorize code, configuration, repository or remote mutations.

1. Inspect relevant call paths and, for motivation questions, relevant history. Use [How](how.md) for runtime behavior/architecture and [Why](why.md) for motivation/history; read the applicable workflow before gathering evidence. For a mixed question, keep mechanics and historical confidence separate. Read applicable full [principle leaves](principles.md) before using their guidance. State `throughput checkpoint: n/a, read-only investigation`.
2. Keep the checklist in the conversation or an explicitly provided external scratch file. Do not create a checklist or install roles inside the investigated repository. Inspect tracked and untracked state before and after without changing it. For stronger enforcement, use a parent read-only sandbox; a role's prose is not a separate permission boundary.
3. Use the selected How/Why route for scoped read-only exploration and synthesis with registered `poteto-agent` when delegation is authorized. Never install a missing role as a side effect of an investigation. Without it, gather evidence in the primary and disclose that no custom role ran.
4. Follow the selected workflow's output: cited architecture/flow for How, seven-category coverage and calibrated historical evidence for Why, or a recommendation with a tradeoffs table. Cite actual files and lines or fetched sources. Distinguish observation, inference and uncertainty. Before answering, audit completion claims against the actual tool record: name a principle as applied only if its full leaf was successfully read, and name a check as executed only if its command/output was observed. Remove unsupported completion claims rather than inferring that familiar guidance or a mental simulation ran. No PR or code change follows automatically; a later requested change routes as a new Feature or Bug fix task.

How and Why are packaged workflow references under the explicit Poteto entry; read-only fallback must be disclosed. Dedicated prose skills and other phase 3 workflows remain pending. Do not claim a separate native `$how` or `$why` entry loaded.
